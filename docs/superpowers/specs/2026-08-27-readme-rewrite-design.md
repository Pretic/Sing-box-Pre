# Sing-box-Pre 与 Pre-cfy README 重写设计

## 目标

将两个项目的 README 从零散追加的“自用二改说明”重写为面向公开用户的项目文档，准确反映当前深度二开状态，并让用户能够快速完成安装、理解核心能力、判断 NAT/单双栈兼容性以及安全地更新或卸载。

目标文件：

- `Pretic/Sing-box-Pre` 的 `README.md`
- `Pretic/Pre-cfy` 的 `README.md`

本次只修改文档，不修改脚本、节点配置、VPS、服务或发布行为。

## 项目定位

两个 README 均直接说明当前仓库由 Pretic 独立维护，属于在上游项目基础上长期演进的深度二开版本，不再使用“自用二改”“只做测试”“保留原作者信息、原项目说明和免责声明”等临时性或自我解释式措辞。

保留以下上游信息：

- 上游项目名称、作者姓名及 GitHub 仓库链接；
- 对上游脚本基础和贡献者的致谢；
- 两个 README 现有的免责声明内容；
- Sing-box-Pre 仓库现有 MIT `LICENSE` 及其中的版权声明，原样不动。

删除以下宣传性内容：

- Telegram 群组或交流群链接；
- 个人博客链接；
- 非功能所需的联系方式；
- “强大且易于使用”等宣传性形容词；
- 重复出现的作者、支持和安装推广段落。

安装地址、当前项目互链、上游 GitHub、功能所需第三方服务说明和示例域名不是广告，继续保留。

## Sing-box-Pre README 结构

1. 项目名称与一句话定位。
2. 核心能力和相对上游的主要演进，包括多协议节点、Argo、WARP 分流、订阅、cfy 联动及事务安全。
3. 支持范围：普通 VPS、端口受限 NAT、IPv4/IPv6 单栈与双栈，以及主要 Linux 发行版。
4. 快速开始：交互安装、无交互安装、NAT 端口安装、更新命令。
5. 菜单与快捷命令。
6. 节点和端口规则，明确质量优先及不可用能力不硬凑。
7. WARP 分流、身份轮换和多平台检测。
8. 基础订阅、cfy 综合订阅及可选 Cloudflare HTTPS 订阅。
9. 常用环境变量与持久化文件契约。
10. 更新、卸载、故障隔离和回滚边界。
11. 上游项目与致谢。
12. 原免责声明。

现有系统徽章墙改为文字支持列表，避免视觉噪声和不必要的第三方图片请求。

## Pre-cfy README 结构

1. 项目名称与一句话定位。
2. 核心能力：VLESS 模板、Cloudflare 官方 IP、第三方优选源、运营商和地址族分类、质量优先筛选。
3. 与 Sing-box-Pre 的边界和菜单联动。
4. 双栈与单栈输出规则：双栈每运营商最多 3 个 IPv4 加 3 个 IPv6，IPv4 在前；单栈每运营商最多 5 个；有效候选不足时不补齐。
5. 快速安装、更新、运行、查看最近结果和常用变量。
6. NAT、客户端地址族与可选健康探测说明。
7. 订阅文件、生成代际、锁、原子发布和失败回滚契约。
8. 依赖与卸载。
9. 上游项目与致谢，只保留作者 GitHub/上游仓库，不保留博客和群组。
10. 原免责声明。

重复的“命令速查”“已安装后如何更新”“一键新装与运行”合并为一套流程。

## 内容准确性约束

- 所有菜单编号、命令参数、默认值、端口关系和文件路径以当前脚本为准，不从旧 README 猜测。
- 不把可选协议写成默认协议，不承诺固定 WARP 国家、固定 IP 或一定解锁。
- 明确 WARP 分流不修改宿主机默认路由，cfy 不进入日常数据转发链路。
- 明确 cfy 保持独立项目、独立命令和独立更新能力，Sing-box 菜单仅安全安装和调用。
- Cloudflare HTTPS 订阅仍是可选项，不要求所有公开用户配置域名或 API token。
- 不加入节点永久改名等已经明确取消的功能。

## 验证标准

- 两个 README 不再出现 Telegram、个人博客、交流群、联系方式和宣传性措辞。
- 两个 README 仍包含正确的上游仓库、原作者署名、致谢和免责声明。
- Sing-box-Pre 的 `LICENSE` 没有变化。
- 安装、更新、卸载、菜单参数、端口、候选数量和订阅文件路径均能在当前脚本中找到对应实现。
- Markdown 标题层级连续，代码围栏成对，表格列数一致，内部没有重复章节。
- 除两个 README 和本设计说明外，不产生其他工作树改动；既有无关改动不暂存、不覆盖。
