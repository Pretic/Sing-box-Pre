# Sing-box-Pre 系统加固设计

日期：2026-08-16

## 目标与范围

本轮仅维护 Linux VPS 主脚本 `sing-box.sh`、相关 Shell 测试和文档，不修改 Node、Python、PHP、Java、Go 等容器包装器。

目标是在不改变现有协议、节点格式和正常转发链路的前提下，提高安装、管理、WARP、订阅、NAT 与单/双栈兼容性。任何新增检测只在安装、管理、优选或 WARP 操作时运行，不成为常驻数据面组件。

## 不变约束

- 不自动更换现有节点端口、UUID、Reality 密钥、Argo 域名或 WARP 身份。
- 不自动运行 cfy，不在升级过程中重选 Cloudflare 候选。
- 不增加数据库、常驻订阅转换器或周期测速守护进程。
- 不修改用户已有的无关 Nginx 虚拟主机、防火墙策略、Docker/NAT 规则。
- 既有菜单编号、基础节点 URL 和 cfy 可消费的 VLESS-WS-TLS-Argo 模板保持兼容。

## 设计

### 1. 本地管理脚本与更新

安装时将经过语法检查的管理脚本保存到固定本地路径，`sb` 直接运行该副本。显式更新才访问远端，并采用“同目录临时文件 → `bash -n` → 备份上一版 → 原子替换”的流程。更新失败时继续使用原脚本。

`/usr/local/bin/sing-box` 必须指向真正的 sing-box 二进制；`sb`、`/usr/bin/sb` 才指向管理脚本包装器。离线或 GitHub Raw 不可访问时，现有管理功能仍可使用。

### 2. 安装与端口模型

保留当前基准端口加偏移量的默认行为，同时允许分别设置 Reality、Nginx、TUIC、HY2 和 Argo 端口，供非连续端口的 NAT VPS 使用。

所有端口在写配置前验证：必须为 1–65535 的整数、不得重复、不得溢出；自动安装还需检测本机监听冲突。仅 Argo 场景不强制要求额外公网映射。

依赖安装只刷新包索引并安装缺失依赖，不执行全系统升级。任一关键依赖、配置检查或服务启动失败时，安装必须非零退出并说明失败阶段，不得打印成功。

### 3. 单栈与双栈

脚本通过路由、地址和 socket 能力判断 IPv4/IPv6，而不是依赖 `ping`。IPv4 单栈使用 IPv4 可绑定地址；IPv6 单栈使用 IPv6；双栈优先采用单个可覆盖双栈的监听方式，若系统启用了 `bindv6only` 则生成明确的双监听配置。

Nginx 仅在系统支持 IPv6 时生成 `[::]` 监听。节点输出继续遵循“IPv4 在前、IPv6 在后”，缺少某一地址族时不输出无效节点。

### 4. 防火墙与 NAT 安全

只添加脚本实际拥有的端口规则，不改变 firewalld zone target、INPUT/FORWARD/OUTPUT 默认策略。

HY2 端口跳跃使用脚本专用 chain 或带唯一 comment 的精确规则；删除时只删除本脚本规则，绝不 flush PREROUTING。卸载也只回滚脚本记录的规则。

### 5. 凭据和配置权限

脚本默认 `umask 077`。包含 UUID、Reality 私钥、WARP、Argo JSON/token 或代理凭据的文件使用 `0600`。固定 Argo token 不写进 world-readable unit，也不通过交互明文回显；服务从 root-only 凭据文件读取。

Socks/HTTP 出站健康检查使用本机 `curl --proxy`，完整代理 URL 不发送给第三方检测站点。

### 6. 出站与路由事务

新增、修改、删除代理出站都在临时配置中完成，随后运行 sing-box 配置检查并受控重启。删除被 `route.final` 或规则引用的出站时，同时回退到 `direct` 或要求明确替代项。检查或重启失败时恢复全部相关文件。

合法的现有 `direct` outbound 原样保留，WARP 修复只在缺失时创建，不覆盖 `bind_interface`、routing mark 等用户字段。

### 7. WARP 生命周期

注册和检测函数的 stdout 只输出机器可解析数据，进度信息写 stderr。身份切换覆盖 account、state、endpoint 和生产配置的完整事务，INT/TERM 分别以非零码退出并恢复旧状态。

候选启用后必须再次确认：WARP 已开启、出口 IP 与旧 IP 不同、选定解锁项仍符合要求、生产 sing-box 服务为 active。回滚不完整时立即中止并保留候选凭据及恢复说明，不继续下一轮。

旧设备云端删除失败时，凭据以 `0600` 保存到待删除目录，后续重试成功后再移除。成功与失败状态都缓存；失败使用较短 TTL，避免菜单离线时反复阻塞。

Netflix、Disney、ChatGPT、Gemini 检测必须区分“解锁”“受限”“检测失败”。模糊页面、403、空响应或缺少地区证据不得判定解锁。

### 8. 与 cfy 的订阅契约

文件所有权：

- Sing-box 拥有 `url.txt`、`base-sub.txt`。
- cfy 拥有 `cfy-url.txt`、`cfy-sub.txt`。
- 两者都通过同一个发布函数构建 `all-url.txt`、`all-sub.txt`、`sub.txt`。

发布统一使用 `/etc/sing-box/.subscription.lock`。内部文件权限统一为 `0600`，只有真正对外服务的 `sub.txt` 为 `0644`。明文先精确去重，再从同一份明文生成两个 Base64 文件，避免并发时三者不一致。

Sing-box 更新 UUID、CFIP 或临时 Argo 域名时，只重写它拥有的基础节点，再在锁内重新发布；不得把旧 cfy 结果重新当作基础模板。

### 9. 订阅与 Nginx

关闭节点订阅只禁用本脚本 server block 或专用订阅服务，不停止整套 Nginx。HTTP token 轮换、HTTPS 启停和 Cloudflare DNS 修改采用备份与回滚；Cloudflare HTTP 200 但 `success:false` 视为失败。

## 错误处理

- 所有远端下载设置连接和总超时，HTTP 错误必须失败。
- 所有生产配置先静态检查，再原子替换和 reload/restart。
- 失败信息必须指出保留了什么、回滚了什么、用户是否需要手动恢复。
- 自动模式不得因部分成功而返回 0。

## 测试与验收

- 为每个修复先增加可复现失败的测试，再实现修复。
- 覆盖端口边界、重复、非连续 NAT 映射和端口占用。
- 覆盖 IPv4 单栈、IPv6 单栈、双栈及 `bindv6only=1` 配置生成。
- 覆盖防火墙默认策略不变和无关 NAT 规则保留。
- 覆盖离线运行 `sb`、更新失败回滚和二进制链接正确性。
- 覆盖凭据权限、unit/命令行不含 token、代理密码不外发。
- 动态覆盖 WARP 首次注册、同 IP 拒绝、信号回滚、服务 active、旧设备待删除及四类解锁检测。
- 与 cfy 的契约测试覆盖首次/二次生成、并发发布、UUID/域名变化、精确去重和文件权限。
- 当前 VPS 部署后，sing-box 配置检查通过，sing-box、Argo、订阅服务保持 active，部署前后订阅内容和出口路径没有非预期变化。

## 发布策略

在隔离分支完成并经过独立审查后合并到 `main`，与已有本地 WARP 提交一起推送。VPS 同步前创建时间戳备份；先安装管理脚本，再进行不改变节点内容的权限与链接迁移，最后完成服务和订阅验证。
