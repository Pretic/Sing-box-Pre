# WARP 实现说明

## 状态显示

首页的“WARP 分流”根据有效出站配置、业务分流规则和 sing-box 服务状态显示“已启用”“未启用”“核心未运行”“配置异常”或“未配置”，不再使用检测缓存驱动首页状态。

“已启用”表示业务规则已启用，不等于所有平台可用。`sb --warp-health` 用于单独检查 IPv4、IPv6 连通性。常规菜单显示不发起平台请求，也不注册身份。

## 平台检测

ChatGPT 使用网页端 GET 请求，不再用 iOS 入口的响应否决网页端。检测区分明确的地区限制、请求拒绝、网页验证、HTTP 异常和网络超时。仅取得可信应用页面时显示“网页可达”；这不是登录、会话或对话成功的证明。

网页验证和未知响应不会作为自动优选的成功条件。Gemini 超时仍属于未确认结果，不等同于地区封锁。

## 候选选择

按平台优选会分别检查候选 IPv4、IPv6，不因 IPv4 与原出口相同就跳过该地址族。所选检测通过且正式核心复核成功后才提交；失败时保留旧配置。

正式身份的检查复用运行中的 sing-box，不另启使用同一身份的 WireGuard 实例。独立候选可以在隔离的临时进程中预检。宿主机没有原生 IPv6 时，也可通过可用的 IPv4 底层连接使用 WARP IPv6 出站。

## 升级兼容

旧版附加的查询网站分流功能已移除。首次使用新版本时，仅清理能精确识别的旧内置规则；遇到被用户修改过的规则会停止自动处理。清理已运行实例的规则需重启一次核心，不改变其他业务规则或系统默认路由。

## 测试

相关测试覆盖 HTTP 分类、地址族选择、状态显示、旧规则清理、重复执行和失败回滚。测试使用模拟响应，不代表某个真实出口当前已被目标平台接受。
