# WARP 状态检测与参考实现

## 2026-09-19 当前实现

本节说明当前代码；后面的 2026-09-05 对照属于历史记录，不能用旧的“临时代理检测”描述替代当前行为。

- 主菜单只读取配置和有时效的缓存，不自动进行网络探测、注册或服务重启。缓存成功不代表实时连通或全部平台可用。
- `sb --warp-health` 分别检查 IPv4、IPv6，通过正在运行的 sing-box 核心及同一套正式 WARP endpoint 完成。首次初始化三个带随机认证的回环健康入口时需重启一次核心，入口只监听 `127.0.0.1`。
- 正式身份的状态检测、提交后的验证不再另外启动使用该身份的 WireGuard 实例。尚未提交的独立候选仍可在临时进程中预检；候选身份与正式身份分开。
- 连通、出口变化、平台可用分别判定。宿主机无原生 IPv6 不代表 WARP 内的 IPv6 不可用；一切以各地址族实测结果为准。公网 IPv6 可能随连接变化，不能当作固定身份标识。
- `sb --warp-check-sites` / `sb --warp-check-sites-off` 管理经过节点的 IP 查询流量，不接管操作系统默认路由。客户端直连访问查询网站不受服务器该规则影响。
- 有界候选筛选仅在所选平台全部通过且提交后验证成功时启用新身份。超时不能标成已解锁；失败保留旧身份，恢复异常单独报告。

代码入口见 [sing-box.sh](../sing-box.sh)，日常用法见 [README](../README.md)。

### 本次授权测试的实际边界

在一台 Debian 12、宿主机仅有原生 IPv4 的测试 VPS 上，完成了正式核心 WARP IPv4/IPv6 连通检查、一次有界身份更换及更换后双栈复核。该次 IPv4 保持不变，IPv6 出口发生变化；没有改变宿主机默认路由。

状态菜单完成逐平台探测。一轮 ChatGPT 与 Gemini 联合自动优选检查了 5 个候选，没有找到同时满足两项条件的结果，脚本按失败路径退出并保留原身份。不能把这个结果描述为“全部解锁”。平台结果只反映当时的脚本探测，不保证特定账号、实际播放或以后持续可用。

这些测试不等同于 Win11/Android 客户端端到端测试、三网带宽对照、原生双栈宿主机完整覆盖或长期稳定性验证。

当时的调整包括先输出握手进度、逐项显示结果、复用完成握手的临时代理、保留严格的平台成功条件。**其中“用临时代理检测正式身份”的实现已被 2026-09-19 的正式核心验证替代。**

历史记录中的 0.01 秒首条反馈、约 25.6 秒完成一轮状态显示，只是当次测量，不作为当前耗时保证。历史 DNS 对照未证明临时 HTTPS DNS 能消除全部平台失败；解析故障、平台拒绝和检测超时仍须分别处理。

本次没有安装其他管理器的系统级 WARP 组件。菜单 10 的第三方入口校验也不代表其后续所有脚本均已审查或可安全叠装。
